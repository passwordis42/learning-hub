# 游戏原型的 AI 开发守则

把这份文件和你确认的规则交给负责开发原型的 AI。网站的 AI 学习工坊只输出问题、检查项或获准规则的原文规格。你决定是否带到游戏仓库，网站不会执行补丁或修改游戏文件。

## 1. 玩家看得见或感受得到的行为由学习者决定

学习者先写目标体验、设计理由和实测证据或待验证假设。每条获准规则在独立一行，包含四个字段。

```text
触发：〈操作或事件〉；条件：〈生效条件〉；结果：〈状态或反馈变化〉；例外：〈边界行为〉
```

仅当学习者确认无需条件或例外时，该字段才能填「无」。规则涉及数值时，一并写明取值、单位、起始状态和何时重置。只实现本次逐条确认的规则及其准确执行所需的技术代码。任何改变玩家输入、反馈、状态、选择、奖励或时机的行为都须能指回一条获准规则。

## 2. 先给实现计划，遇到待定项先问

开发 AI 在编辑前先列出规则编号、拟改文件或配置、引擎默认行为和拟验证场景。碰到待定数值、含义不明的状态、规则冲突或未规定的玩家可见行为时，列出具体问题，等学习者作出决定后再执行受影响的实现。可继续已授权且独立的工作。

可以搭场景、做占位素材、组织代码或实现已约定的记录。直接使用模板时，先检查并隔离模板带来的未授权玩法。为了省事添加的默认值、自动纠正与兜底行为，也按同一套规则审查。

## 3. 查找藏在实现里的玩法

| 检查位置 | 核对的问题 |
| --- | --- |
| 输入与时机 | 连按、长按、输入缓存和容错是否有依据？冷却从哪一帧或哪个事件开始？ |
| 碰撞与移动 | 碰墙是停止、滑动还是反弹？穿过边缘、同时命中与出生重叠怎样处理？ |
| 反馈与提示 | 自动瞄准、方向箭头、声音、震动或容错提示是否改变了挑战与理解？ |
| 奖励与随机 | 隐藏掉落、保底、奖励叠加、默认概率和随机种子对应哪条规则？ |
| 失败与重置 | 失败、重开、切换关卡和重读存档时，哪些资源、计时器和状态会恢复？ |

对照最终变更，逐条注明来源规则。发现与已确认规则无关的行为，先隔离并报告。学习者决定补写规则还是移除行为。

## 4. 用手动试玩验收

AI 提供可重复的操作步骤、预期结果和涉及的规则。学习者自己跑正常路径、条件不满足、例外、重置四类场景，留下版本号和实际结果。调参实验保留基线，明确记录本轮变化。真实玩家的观察和原话支持下一轮设计取舍，AI 可以整理脱敏记录。
